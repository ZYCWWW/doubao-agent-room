# 状态机建模

> 任何有阶段、有生命周期、有规则流转的过程，都可以用状态机表达——**状态是离散的锚点，转移是条件的触发**。

## 建模四要素
1. **状态集合**：对象/过程可能处于的离散状态（含初始态、终态）。
2. **转移条件**：什么事件/条件触发状态改变。
3. **动作**：转移发生时执行什么。
4. **非法转移**：不允许的路径 → 检测到即逻辑漏洞。

## 使用场景
- Agent 循环：`初始 → 思考 → 工具调用 → 观察 → 完成/超时`。
- 任务生命周期：`待办 → 进行中 → 待验证 → 完成/失败`。
- 对话/审批流：`草稿 → 已提交 → 审批中 → 通过/驳回`。

## Agent 使用要点
- 分析流程时先画状态图：穷举状态 → 列出转移 → 找出缺失路径。
- 排查"卡死/乱序"问题：检查是否缺转移条件、是否有多余的非法转移被允许。
- 设计新流程时用状态机约束，避免自由文本导致歧义。
- 状态必须可观测（有判定依据），否则无法验证。
