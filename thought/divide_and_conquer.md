# 分治与系统分解

> 处理复杂问题的第一招：**把大问题变小**。拆到子问题可独立求解为止。

## 拆解原则
1. **可独立**：子问题之间尽量少耦合（不共享可变状态）。
2. **可合并**：子结果能按规则合成总结果（和/拼接/取优）。
3. **递归结构**：子问题与原问题同构 → 递归或循环套用。
4. **明确接口**：每个子任务定义输入/输出，边界清晰。

## 两类拆法
- **按结构拆**：系统按模块/层切分（前端/后端、核心/服务/数据）。
- **按过程拆**：任务按阶段切分（收集→分析→验证→交付）。

## Agent 使用要点
- 大任务先列子任务清单（每项可独立完成、可验证），再逐项攻克。
- 拆解失败信号：子任务之间互相等待 → 重新划分边界。
- 排查复杂 bug：二分定位——把链路对半切，判断问题在前半还是后半。
- 合并子结果时检查一致性（量纲、口径、格式统一）。
