## 二、第一步：记忆架构复盘——诊断出的 8 条缺陷

原有三层（知识库 / 记忆 / 想象空间）只是靠 `metadata["type"]` 在一个 Chroma 集合里过滤，问题：

1. 记忆、知识、技能混在一个集合，隔离弱，容易误召回；
2. 衰减没有边界——情景记忆和事实记忆一律衰减；
3. 想象空间只是文件堆，没有索引，Agent 在长沙盘里找 MD / 截图很慢；
4. 技能只写不维护：没有版本、没有失效标记，软件一升级旧步骤就成了错误技能；
5. 没有遗忘策略：衰减只让分变低，不归档不清理，向量库持续膨胀；
6. 没有关联：推理草稿、学到的技能、情景记忆之间无法串成一条链路；
7. 没有溯源：知识 / 技能 / 记忆不绑定证据（哪张 VL 截图、哪次网页阅读、哪次软件操作）；
8. 召回策略单一：统一相似度，不分优先级。

## 三、优化后的架构：保留三层命名，拆成四个集合

| 域 | 集合 | 关键规则 |
|---|---|---|
| 知识库 | `knowledge_fact` | 事实、文档摘要、网页提取内容，**无衰减、永久** |
| 知识库 | `knowledge_skill` | 软件操作技能，带 `version` / `is_valid` / `software_version` / `evidence_ref` / `confidence` |
| 知识库 | `knowledge_rule` | 系统规则、权限约束、工具规范（ACL、VL 使用约束、Agent 行为规范） |
| 记忆 | `episode_memory` | 只放对话、观测、推理结论；`base_score - decay_rate × time_delta`；`SAVE=6.0` 入库、`ARCHIVE=2.0` 移入归档表（仍可审计、可手动恢复） |
| 想象空间 | 文件 + 每会话一个 **sqlite 轻量索引** | 只存摘要与标签，细节再读原 MD / 图送 VL；默认不参与全局召回，只在当前会话内检索 |

召回优先级（硬编码进 Prompt 与检索函数）：

```
1. knowledge_skill（软件技能，最高）
2. knowledge_fact / knowledge_rule（静态知识、系统规则）
3. episode_memory（近期情景记忆）
4. 当前会话想象空间的 sqlite 索引（草稿、截图记录）
```

配套新增：证据溯源（任意一条知识 / 技能 / 记忆可反跳回沙盘原始证据）、技能版本管理（新版入库旧版 `is_valid=false`）、
跨会话记忆隔离（默认不加载别的会话）、沙盘索引加速（不给海量截图描述灌向量库）。

## 四、第二步：二次巡检——16 个问题，按等级排

- **致命（3）**：
  1. pyautogui 高 DPI / 多显示器坐标错位 → 用 `ctypes` 取 DPI 换算、点击后小区域截图送 VL 校验、失败最多重试 2 次即停、设连续操作上限；
  2. ACL 只校验路径、不校验进程 → 子进程监控，只允许白名单目录内派生进程；
  3. VL 编造路径与按钮文字 → 输出后独立校验器 `os.path.exists()` 验证、Prompt 禁止编造、路径一律 resolve 成绝对路径再送 ACL。
- **高风险（4 条，编号 4–7）**：技能重复写入不标失效（相似度 0.85 命中即新增版本）、自学失败也生成技能（加 `task_success`，失败只进沙盘）、
  Chroma 无集合隔离（拆 4 个 collection）、审批队列无会话隔离（队列 key 带 `session_id`）。
- **逻辑缺陷（编号 8–11）**：自学固定 `sleep(3)` 阻塞（改轮询 + 90s 超时 + 菜单栏「帮助」兜底）、沙盘不过期（`sandbox_keep_days`）、
  技能调用不重校 ACL（每次调用重校验，权限变了直接拒）、视觉预览 sid 不同步（URL 带 `?sid=`）。
- **性能与体验（12–14）**：检索不封顶（强制 `top_k`）、无 LLM/VL 超时熔断（超时 + 最多 2 次重试，失败中断任务而非卡死）、
  `audit.log` 粒度不足（独立审计日志：时间 / sid / 操作者 / 工具 / 入参 / ACL / 审批 / VL / 技能变更 / 归档）。
- **隐性架构缺陷（15–16）**：实体间无关联链路（统一加 `evidence_ref`）、无导出（知识库 jsonl、单会话记忆、沙盘打包，面板加导出按钮）。

## 六、收尾时抓到的真 bug：`config_loader.get()` 返回整个 section

全文最后是 10 轮排查的现场记录，结论很干净：

- 现象：`llm_client` 的 `self.url`、`self.model` 全是字典，而不是字符串。
- 根因：`config_loader.get(section, key)` 在 **key 不存在时返回整个 section 字典**，而没返回默认值；日志同时打出 `config.toml not found, use default config`（工程根目录当时没有 `config.toml`）。
- 处理：先采用**方案 1**（绕过 loader，直接读 `DEFAULT_CONFIG["ollama"]`）把链路跑通；
  **方案 2（治本）**——修 `config_loader.get()`——留在待办里。
