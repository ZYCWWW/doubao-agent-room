# 记忆系统说明

> 这份文档讲的是**机制**，不是内容。
> 记忆里装的东西属于使用者本人，不进公开仓库；这里只说明它怎么工作、存在哪里、怎么启用。

---

## 一、记忆放在哪

记忆是**运行时产生的数据**，不随代码发布。默认位置：

```
agent_memory_db/          # Chroma 持久化目录
docs/conversations/       # 每日对话纪要（使用者可自行归档）
```

这两处都在 `.gitignore` 里。仓库只带代码和机制，不带任何人的记忆内容。

想从零开始：删掉 `agent_memory_db/` 即可，程序会在首次启动时重建空集合。

---

## 二、四分区结构

| 分区 | 定位 | 写入时机 |
|---|---|---|
| `memory_core` | 热记忆：当前阶段最重要的事 | 评分高的交互、明确结论 |
| `memory_cold` | 温记忆：暂时用不上的细节 | 从 core 下沉 |
| `memory_archive` | 冷存档：长期不再引用 | 定时任务按小时迁移 |
| `reflection` | 反思条目 | 预留，当前无调用方 |

除四分区外，保留了四个旧集合（`episode_memory` / `knowledge_fact` / `knowledge_skill` / `knowledge_rule`），**只读**、已标记迁移完成，新写入一律进分区。

代码位置：`services/memory_service.py`（分区、迁移、下沉、访问计数）、`core/memory/`（TF-RI 排序、注意力、反思、溯源）。

---

## 三、检索怎么排

召回不只看向量相似度，而是 **TF-RI**（term frequency × recency × importance）加权：

- **相关度**：向量距离；
- **新鲜度**：越近写入权重越高；
- **重要度**：显式标记或评分推出的权重；
- **访问计数**：被反复引用的条目会加权。

命中后在上下文里带上溯源信息（来自哪次交互、什么时候写的），避免模型把自己的推测当成既定事实。

---

## 四、为什么记忆不进公开仓库

原因很直接：**记忆的内容就是使用者的生活**。

对话纪要里会出现本人的原话、家人、住所、设备、工作内容、情绪。这些对别人没有参考价值，对本人却有风险。所以这里的处理原则是：

| 东西 | 是否进仓库 |
|---|---|
| 代码、机制、架构文档 | 进 |
| 每日对话纪要（原始版） | 不进 |
| 对话逐字原文 | 不进 |
| Chroma 记忆数据 | 不进 |
| 脱敏后的技术日志 | 进（见下） |

---

## 五、公开版提供了什么

`docs/tech-log/` 是按同一批日期整理的**技术日志**：

- 保留：做了什么、遇到什么问题、怎么解决的、踩过哪些坑；
- 去掉：本机路径、设备型号、使用者称呼、会话标识等一切可定位到个人的信息。

也就是说——**过程公开，人隐去**。想看这个项目是怎么一步步长起来的，读 `docs/tech-log/`；想知道某一天具体聊了什么，那部分只留在使用者自己的硬盘上。

---

## 六、自己启用记忆

1. 装好依赖（见 README）；
2. 正常启动面板或 `main.py`，首次运行会自动在 `agent_memory_db/` 建空集合；
3. 需要长期归档对话时，用 `tools/archive_conversation.py` 导出到 `docs/conversations/raw/`；
4. 归档目录已在 `.gitignore` 内，不会被误提交。

如果你的归档需要纳入版本管理，请自行确认内容不含个人信息后再改 `.gitignore`。
